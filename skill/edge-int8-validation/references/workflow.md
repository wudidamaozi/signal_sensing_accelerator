# 工作流与验证来源

## 使用与迁移

安装Python 3.11+及NumPy（本包验证环境为Python 3.12、NumPy 2.4.6）。从独立整数参考与待验证实现导出同一输入的NPZ。字段名、字节序、形状与dtype由使用者约定，`--keys`显式选择层。保留偏置、移位、舍入、饱和、ReLU及池化顺序。仅预测类别相同不足以替代数值检查。

时序JSON字段示例：
```json
{"part":"xc7z020clg400-1","clock_period_ns":20.0,"scope":"routed compute subsystem","setup_slack_ns":0.20,"hold_slack_ns":0.01,"route_errors":0}
```
这些数字是格式示例。用自己的实现报告替换。摘要工具拒绝非有限数、负裕量、非正时钟和路由错误；它不自动解析厂商报告，也不检查未约束路径、器件容量或DRC严重程度。

## 可复用提示词

下面是根据本队已执行流程整理的模板，可用在图像、声音或时序CNN。模板本身的跨题目效果尚需使用者验证；校验脚本的效果有独立测试。

> 输入：算法与整数契约、各阶段周期、CPU/缓存/阵列接口、当前源身份。请先列出CPU计算、数据搬运、等待与MAC各自占比，说明统计口径；给出一项最小改动及预期减少的阶段。保持模型、输入和计时边界，列出逐层黄金值校验与真实回退命令。只有运行结果满足契约时才接受；失败也生成独立summary。

> 输入：器件、约束、完整utilization/timing/route/DRC报告及源码SHA。请区分资源容量和时序收敛，定位关键路径及存储映射。为候选写出假设、资源代价与验证命令；保留原始报告，分别列仿真、实现估计和板上测量。

## 从观察到规则

| 观察或失败 | 提炼的动作 | 已验证效果 | 边界 |
|---|---|---|---|
| P33夹具缺bias/shift；C边界首次按错误元素宽度解码 | 参数和整数边界一起冻结；显式dtype | 2026-10-23对80个class/SNR输入的两套C实现共160组边界检查；单字节错误被拒绝 | 共享的错误整数契约仍需独立算术检查 |
| M29资源能容纳而100 MHz时序失败 | 资源与setup/hold分开验收 | 历史实际布线摘要通过，负hold注入被拒绝 | 摘要通过不代表板级I/O或Fmax签核 |
| 不同本地RAM、预载和计时范围导致对照口径变化 | summary保留工作负载、时钟和边界；配对原版/修改/回退 | 项目按源身份保存优化及回滚记录 | 条件改变时不直接算同条件加速比 |

历史证据摘要及来源SHA见包内 `../../evidence/provenance.json`（独立安装单个Skill时，工作流表格已保留必要事实）。新增的脚本正反例运行记录位于技能包 `evidence/`。

## 排查顺序

1. 缺字段：核对导出器的参数与层清单，再重导出。
2. dtype/shape失败：检查布局和字节序；显式修改适配器，保留原输出。
3. 首个边界字节失败：从偏置、符号扩展、舍入、饱和和层间量化依次定位。
4. 时序失败：查看同源布线报告的关键路径；重新实现后生成新摘要。
5. 周期变化但MAC busy不变：优先分解装载、启动、轮询和写回。
